# NanoLabs platform access

- Platform identities (`PlatformAdmin`) are strictly separate from commerce users (`User`). No impersonation, cross-tenant data browser, or public self-registration.
- **Domain boundary**:
  - `PLATFORM_DOMAIN` (default `onlymarket.nanoapps.ar`) serves the SuperAdmin console (`/superadmin/login` and `/superadmin`) exclusively. Tenant routes redirect to SuperAdmin.
  - `TENANT_BASE_DOMAIN` (default `nanoapps.ar`) serves individual commerces via `https://{slug}.{TENANT_BASE_DOMAIN}`. Tenant login resolves the commerce from the request hostname, renders the commerce name, blocks `/superadmin*` with `404`, and refuses login when the commerce is non-existent, suspended, or expired.
  - Session cookies are **host-only** (never shared across subdomains) and validated server-side against the request hostname.
- **Slug collision prevention**:
  - Validates DNS syntax, reserved labels, PostgreSQL uniqueness and atomic local provisioning. Shared namespaces fail closed: `nanoapps.ar` and `nanoapps.site` cannot allocate new tenants until every writer participates in a shared atomic reservation protocol. The current router has no such protocol; its 404 is not proof of availability (timeouts and cached negatives also produce 404). `SLUG_CHECK_STRICT=false` does not bypass this restriction, including in bootstrap.
  - A future exclusively owned domain may explicitly set `TENANT_NAMESPACE_MODE=exclusive`. This is an operational ownership declaration, not a collision check. It cannot override the known shared NanoLabs domains. Local `localhost` is isolated. Configured router/sibling probes fail closed on errors, redirects from ask endpoints and unexpected statuses.
  - Dynamic routing on `*.nanoapps.ar` uses `GET /api/internal/caddy/ask?domain=...` returning `204` for valid OnlyMarket hosts and `404` otherwise.
  - `ask` accepts exactly one DNS name; ports, URLs, wildcard names, lists, whitespace and duplicate parameters return 400. Existing suspended/expired tenants retain routing ownership (204) so their blocked screen remains reachable; this never grants application access.
- `Host` is authoritative because NPM and nanoapps-router preserve it. Contradictory or malformed `X-Forwarded-Host` is rejected. Forwarded scheme cannot control redirects. No implicit localhost/IP aliases exist outside explicit local configuration. Unknown hosts cannot reach the platform or tenant application.
- Create the initial platform operator via `node scripts/bootstrap-platform.mjs` inside the app container using temporary environment variables `PLATFORM_BOOTSTRAP_EMAIL` and `PLATFORM_BOOTSTRAP_PASSWORD` (min 12 chars). Do not commit credentials or put them in shell history.
- Enable `PLATFORM_ADMIN_ENABLED=true` in the runtime env and recreate only the OnlyMarket app container. HTTPS required. Global and per-account login throttling (`LoginLimit`), 4-hour session, `SameSite=Strict` cookie scoped to `/superadmin`, and audit trail (`PlatformAudit`).
- Hub `GET /api/integrations/nanolabs/tenants?offset=0` implements `nanolabs.saas.tenants.v1`, product `onlymarket`. Runtime `HUB_INTEGRATION_TOKEN` must be a unique random token of at least 32 bytes. Missing/invalid token returns `401`; only `GET` is allowed (`405` otherwise); no user emails or financial records are exposed.
